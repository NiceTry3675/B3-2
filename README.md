# Mini Git

커밋을 노드로, 부모와 자식의 관계를 간선으로 표현한 작은 버전 관리 프로그램이다. 브랜치를 나누고 다시 병합해 보면서 같은 그래프를 로그, 경로, 조상 탐색이 어떻게 다르게 읽는지 확인할 수 있다.

## 실행

Python 3.10 이상에서 프로젝트 디렉터리로 이동해 실행한다. 외부 패키지 설치는 필요 없다.

```sh
python main.py
```

`mini-git>` 프롬프트가 뜨면 명령을 입력한다. 명령 이름은 대소문자를 구분하지 않는다. 공백이 있는 인자는 큰따옴표나 작은따옴표로 감싼다. 한 세션에서 `INIT`은 한 번만 실행할 수 있다. `exit` 또는 `quit`로 종료하면 메모리에 보관한 이력이 사라진다.

## 브랜치를 나누고 다시 합쳐 보기

새 세션에서 아래 명령을 한 줄씩 입력한다. 해시는 생성 순서대로 붙으므로 같은 예시를 다시 실행해도 같은 경로가 나온다.

```text
init "Alice Kim"
commit "Initial commit"
branch feature
switch feature
commit "Add login"
switch main
commit "Add payment"
merge feature
log
path 000001 000004
ancestors 000004
search "ADD login"
search --author="Alice Kim"
```

```text
         000002 (feature)
        /      \
000001          000004 (main, HEAD)
        \      /
         000003
```

- `log`는 모든 브랜치의 커밋을 보여 준다. `000004`는 두 부모 `000002`와 `000003`이 모두 출력된 뒤에 나온다.
- `path 000001 000004`에는 길이 2인 경로가 두 개 있다. 두 번째 해시가 더 작은 경로인 `000001 -> 000002 -> 000004`가 선택된다.
- `ancestors 000004`는 부모 둘과 공통 조상 `000001`을 한 번씩 출력한다.
- `search "ADD login"`은 두 단어가 모두 있는 `000002`를 찾는다. 작성자 검색은 입력한 이름과 정확히 일치하는 커밋을 찾는다.

## 명령어

| 명령 | 동작 |
| --- | --- |
| `INIT <user_name>` | 현재 사용자를 설정하고, 첫 커밋이 없는 `main` 브랜치에서 시작한다. |
| `BRANCH <name>` | 현재 브랜치와 같은 커밋을 가리키는 브랜치를 만든다. |
| `SWITCH <name>` | 작업할 브랜치를 바꾼다. |
| `COMMIT <message>` | 현재 브랜치 끝에 커밋을 추가한다. 빈 브랜치의 첫 커밋은 부모가 없다. |
| `LOG` | 저장소 전체에서 부모가 자식보다 먼저 나오도록 출력한다. |
| `LOG --sort-by=date`, `LOG --sort-by=author` | 시간 또는 작성자 이름의 오름차순으로 출력한다. 값이 같으면 생성 순서를 유지한다. |
| `PATH <from> <to>` | 부모와 자식 양방향으로 최단 경로를 찾는다. 연결되지 않았으면 `No path`를 출력한다. |
| `ANCESTORS <hash>` | 부모를 거슬러 올라가 모든 조상을 출력한다. |
| `SEARCH <keyword>`, `SEARCH --author=<name>` | 키워드 또는 작성자 역색인에서 일치하는 커밋을 찾는다. |
| `MERGE <branch>` | 현재 브랜치와 대상 브랜치의 끝을 부모로 하는 커밋을 만든다. 서로 다른 두 끝 커밋이 필요하다. |
| `DIFF <file1> <file2>` | UTF-8 텍스트 파일을 줄 단위로 비교한다. 삭제는 `-`, 추가는 `+`, 공통 줄은 공백으로 표시한다. |
| `BENCH` | 병합 정렬과 삽입 정렬의 실행 시간을 입력 크기별로 비교한다. |

## 코드 읽는 순서

1. **`main.py`**에서 `commit "Add login"`이 어떻게 처리되는지 따라가 본다. `shlex.split`이 따옴표 안의 메시지를 하나의 인자로 보존하고, `run_command`가 저장소에 커밋 생성을 요청한다.
2. **`repository.py`**의 `Repository._record`를 읽는다. `commits`는 해시를 키로 사용해 평균 O(1)에 커밋을 찾는다. `head`에는 브랜치 이름을 저장하고, `branches`에서 그 이름이 가리키는 커밋을 찾는다. 새 커밋은 이미 존재하는 커밋만 부모로 가질 수 있고 부모 정보는 생성 후 고정되므로 사이클이 생기지 않는다.
3. 같은 파일의 **`SearchIndex`**를 살펴본다. 커밋 생성 시 작성자와 메시지의 각 단어에 해시를 등록한다. 단어는 공백으로 나누고 소문자로 바꾸며, 같은 메시지에서 반복된 단어는 한 번만 등록한다. 단일 키워드 검색은 전체 커밋 수와 무관하게 평균 O(1)에 목록을 찾고, 일치하는 커밋이 k개면 O(k)에 결과를 출력한다.
4. **`graph.py`**에서 탐색 방향을 비교한다. 기본 로그는 남은 부모 수가 0인 노드부터 꺼내는 위상 정렬이다. 조상 탐색은 부모만, 최단 경로 탐색은 부모와 자식을 모두 이웃으로 삼아 같은 너비 우선 탐색(BFS)을 사용한다. `PATH`는 목적지에서 거리를 먼저 구한다. 출발지에서 남은 거리가 1씩 줄어드는 이웃 중 가장 작은 해시를 선택하면 최단 거리와 사전순 조건을 함께 만족한다. 세 탐색 모두 최악 O(V + E)이며 V는 커밋 수, E는 부모 연결 수다.
5. **`sorting.py`**에서는 날짜와 작성자 중 무엇을 비교할지 `key` 함수로 전달한다. **`bonus.py`**의 `benchmark`는 크기별로 같은 난수 목록을 두 알고리즘에 전달한다.

## 정렬 성능 비교

| 알고리즘 | 평균 시간 | 최악 시간 | 같은 값의 순서를 유지하는 방법 |
| --- | --- | --- | --- |
| 병합 정렬 | O(n log n) | O(n log n) | 두 목록의 맨 앞 값이 같으면 왼쪽에서 먼저 꺼낸다. |
| 삽입 정렬 | O(n²) | O(n²) | 삽입할 값보다 큰 원소만 오른쪽으로 옮긴다. |

아래는 `bench`를 한 번 실행한 측정값이다. 입력은 고정된 난수 시드로 생성하며, 실행 시간은 환경에 따라 달라진다.

| 원소 수 | 병합 정렬 (ms) | 삽입 정렬 (ms) |
| ---: | ---: | ---: |
| 100 | 0.056 | 0.068 |
| 500 | 0.361 | 1.989 |
| 2,000 | 1.397 | 33.990 |
